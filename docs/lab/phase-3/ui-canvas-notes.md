- Drawn in **MedSync Chroma** (`medsyncchroma` design system copied 13 Oct 2026). Build with the tokens on this branch
  (`app/globals.css`), not the canvas CSS (`lab.css`, `lab2.css`, `lab3.css` are canvas-only).
- Canvas rows: _Quality control_ (1–4) · _Stock, lots and equipment_ (5–7) · _EQA, nonconformities, bedside quality_
  (8–10) · _Registers, HMIS and reports_ (11–13).
- The canvas's own disclaimer: "Illustrative. No real patients. QC targets, SDs, stock levels, EQA scores, counts and
  HMIS figures are examples, not real or signed values. HMIS 105 row codes follow the September 2019 print version
  and must be checked against the live eHMIS dataset."

names on the canvas ("Patient Seven-7", "MS-2026-00007") are placeholders.

## Shared chrome

- Left navigation (`nav.lb-side`, label "Laboratory"): workspace mark "Test Hospital-1"; groups **Laboratory**
  (Worklist, Criticals), **Quality** (Quality today, Quality control, Stock and lots, Equipment, External quality,
  Nonconformities), **Reports** (Daily register, HMIS 105, Lab reports). Counts in the nav are mono, never coloured
  badges. Active item uses the grape (lab) tint.
- Top bar: breadcrumb `Laboratory / … / **page**`, the viewer's role ("Laboratory lead", "Lab technologist ·
  Clinical chemistry"), monogram avatar.
- Chips used throughout (canvas class → meaning → build with):
  - `qs` with check icon → **Passed / In stock / None broken** → neutral `Pill`, check icon.
  - `qs--warn` with circle-alert → **Warning 1-2s · accepted** → amber (`status-caution`) with icon and word.
  - `qs--fail` with triangle-alert → **Failed {rules} · release held / Held** → dark amber (`status-caution-fg-aa`
    on caution ground), icon and word.
  - `qs--none` (dashed) → **Due today / Not run today / New lot · run controls / Due before first use** → dashed
    neutral chip.
  - `lb-chip--due` → **Below minimum / Use first** → amber chip with icon (note: "Use first" on the canvas is amber;
    per Law 11 it is a cue, not a warning, so build it neutral with a word, see artboard 5).
- Hold block (`.hold`, `role="alert"`): triangle icon, bold first sentence, then the next step. Amber, never red.
- Note blocks (`lb-note`, `lb-note--caution`): info or caution icon with a short paragraph.

## Differences between the canvas and the prompt (the prompt wins; §5.14)

- **D-C1** Artboard 5 footnote says average use comes "from tests actually released". ST-4 says average monthly use
  is **issues** over the look-back; released tests only feed the expected-versus-issued check (ST-9). Build ST-4.
- **D-C2** "Use first" is drawn as an amber chip. It is a cue, not a warning; Law 11 keeps amber for warnings, so it
  is a neutral chip with the words "Use first".
- **D-C3** The Quality-today tile "Lots expiring in 30 days" and the stock filter "Expiring in 30 days" hard-code
  the window. The window is an operational setting; the label reads "Expiring within {window}".
- **D-C4** Artboard 13 has no section or priority filter; §5.13 adds both.
- **D-C5** Artboard 11 shows "Download CSV … in DHIS2 data-element order"; the CSV columns are the eHMIS
  data-element and category-option ids from Q4 (not yet obtained, owner action).
- **D-C6** Artboard 12's lab number format (`L-000588`) is illustrative; the register prints the Phase 2 label
  number (`lab_labels.label_no`).
- **D-C7** Screens with no artboard (§5.14): the analyser tab of 5.4, temperature log editor, maintenance checklist
  editor, QC plan editor, acceptance plan editor, HMIS mapping editor, HIV register print, alternative-assessment
  form. Build them from the specification with the same components.
- **D-C8** The canvas uses `qs--fail` for both "Failed … release held" and the per-level rule chip. Per Law 11 the
  dark amber chip is for a **rejected run**; a single rule name inside the run table uses the same dark amber chip
  with its word.
