# ADR-0074 — Assessment as Diagnostic Logic (catalog-driven, support-matched, clinician-selected)

**Status:** Accepted (kickoff GATE A–C run together under "finish up and deploy", 2026-06-14; the catalog spec `diagnosis-catalog-reference.md` supplied by the CSO). Built on `feat/assessment-diagnostic-logic`. **Supersedes** the problem-list model ([ADR 0073](docs/adr/0073-clerkship-problem-list-synthesis.md)) for the Assessment surface.

**Context:** The Assessment listed proposed problems. The rework replaces that with **diagnostic logic**: read the whole clerkship (symptoms + signs + risk factors + abnormal vitals), match captured features against a diagnosis catalog, and surface **ranked, evidence-backed diagnosis suggestions** the clinician selects from — the selected diagnosis then feeds workup (next build). A 4-reader code-mapping fan-out established the substrate: the **TS reasoning maps are the runtime source of truth** (the `«»` guillemets live only in the docs JSON, flagging 151 not-yet-in-catalog free-text features); `riskFactors` are ~65–75% free-text; and there is **no diagnosis→ICD-10 map** (only 19 codes; ~9 match by name). **No migration.**

## Decision

1. **Diagnosis catalog = a RE-PIVOT of the maps, DERIVED at runtime** (`lib/clerkship/diagnosis/catalog.ts`, pure/TDD). `buildDiagnosisCatalog()` inverts every differential across the 17 CSO-signed `REASONING_MAPS` into diagnosis-keyed entries, unioning each diagnosis's supports across the presentations it appears under (recorded as `presentations` provenance), carrying must-not-miss. **One-source-of-truth is structural** — it is computed from the maps, not a parallel hand-maintained file, so a map change flows here automatically and the two can never disagree. `status: from_reasoning_maps` for all (no net-new this pass).
2. **ICD-10 is never fabricated.** A diagnosis links to a code ONLY when its name matches an already-verified `ICD10_CODES` entry (deterministic whole-phrase match; a more-specific variant like "Cerebral malaria" is NOT force-linked to "Malaria, unspecified"). Everything else is `null` — pending web-verified CSO population. `workupRef` is a `null` placeholder.
3. **The matching logic BORROWS the reasoning engine** (`lib/clerkship/diagnosis/suggest.ts`, TDD) — it does not re-implement it. `suggestDiagnoses(scored)` re-presents the engine's `ScoredDifferential[]` (reusing its matched evidence buckets verbatim — `matchedRuleIn`/`supportPresent`/`riskPresent`/`ruleOut`/`refute`) joined with the catalog's ICD-10 + provenance. So the suggestions correspond to the rail; they cannot diverge.
4. **Ranks by support, never asserts.** Must-not-miss floats to the top **regardless of support** (even at low/negative score); the rest follow the engine's score. Honest labelling (suggestion + support-status chip, never a confirmed diagnosis).
5. **The Assessment surface** (`assessment-synthesis.tsx`): Zone 1 (abnormal summary) survives; Zone 2 becomes the diagnostic surface — ranked evidence-backed suggestions with their "why", **Select / Reject / Add-own** (ICD-10 typeahead). Select records the clinician's working diagnosis (carrying the catalog's verified ICD-10) and feeds the **workup seam**; Reject keeps it "considered & excluded" (must-not-miss retained). **Zone 3 (the problem list) is removed.**
6. **Problem-list removal is clean + non-destructive.** The Assessment's problem-list proposer (Zone 3 + the `problem-synthesis` engine + the form's problems-state) is deleted. The **patient longitudinal `problem_list` is unaffected** — it is still fed from PMH at `deriveClinicalObjects` (`pmhProblems`); only the synthesis-proposed problems (now empty) drop out. No migration, no spine change.

## Consequences

- The committed working diagnoses (`encounter_diagnoses`, status working, with catalog ICD-10) are the **workup data contract** — workup hangs off each diagnosis via the catalog's `workupRef` (the next build; not built here).
- **Open follow-ups (flagged for the CSO):** (a) the 151 `«»` free-text features pending curation into the structured Sx/sign/history catalogs (the vocabulary-reconciliation pass — applies to the maps + this catalog together); (b) ICD-10 population for the ~85 diagnoses currently `null` (web-verified, CSO-signed); (c) `supportingSigns` is an empty net-new dimension (the maps don't carry per-diagnosis exam-sign supports yet); (d) support weights are structural (by support type), not per-item clinical judgement — the actual ranking is borrowed from the engine.
- Pre-deploy adversarial review (3 lenses — parity/safety/clean-removal) returned **0 confirmed findings**.
