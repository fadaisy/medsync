# ADR 0059 — Encounter / EMR engine + structured clerkship (the clinical-data spine)

**Status:** Accepted (spine) — CLINICAL-SAFETY + PDPO-critical artifact (2026-06-04). **The migration is GATED (not applied to prod); awaiting CSO sign-off of the access model + schema + clerkship structure** before apply. GATE A design in `docs/encounter-emr-engine-gate-a-proposal.md`; clinical source `docs/clinical/clerkship-clinical-reference.md` (Hutchison's Clinical Methods 24th ed.).
**Context:** The encounter/EMR engine is MedSync's clinical-data spine. The addendum (`encounter-engine-clerkship-addendum.md`) makes the encounter's clinical documentation a **structured Hutchison CLERKSHIP** (history → examination → differential → initial management), not a free-text note, populating the engine's objects. **Spec reconciliation (2026-06-04):** the primary spec **`encounter-emr-engine-kickoff.md` has now been provided** and the build is reconciled against it (the proposal §"Spec reconciliation" records the deltas). The spine designed earlier holds; the material correction is the **access basis** — the kickoff's "never any clinician sees any patient" is the legitimate-basis the repo already implements for the doctor/nurse workspaces, so the engine now converges on it (see Decision 2) rather than its earlier looser predicate.

## Decision

1. **Build ON the existing `encounters` table (migration 0028), don't recreate.** Migration `0040` ALTERs it (+`disposition`, `triage_record_id`, `encounter_class`) and adds the clinical objects: `clinical_documentation` (versioned, append-only clerkship), `encounter_diagnoses`, `problem_list`, `patient_allergies` (the canonical `db/schema/prescribing.ts` object — **shared** with the gated 0039, which also declares it; 0040 creates it **idempotently** and is the **authoritative owner**, superseding 0039's hospital-scoped RLS policy with the relationship-based one), `encounter_medications`, `encounter_orders`/`encounter_results`, `encounter_events` (append-only timeline). **The migration is GATED** (header: do-not-apply-without-named-authorization) — the clinical-data spine is hard-to-reverse; same posture as 0039.
2. **Access model — legitimate-access basis, least-privilege, audited** (`§B` of the proposal; kickoff §2). The engine enforces the SAME basis the doctor/nurse workspaces already use (`lib/doctor/patient-access.ts`, `lib/nurse/patient-access.ts`), resolved strongest-first in `lib/encounter/scope.ts → resolveEncounterAccess`: **`active_encounter`** → **`department_recent`** (30-day window) → **`care_team`** (seam; false today) → **`break_glass`** (unrevoked/unexpired `sa_break_glass_grants`). This replaces the earlier looser "any clinical staff at the hospital" predicate, per the kickoff's "never any clinician sees any patient." **Reception (`is_clinical=false`) never matches.** Clinical **writes go through service-role server actions only** (no client write policy); documentation + the timeline are **hard append-only** (block triggers — corrections create a new version). **⚠️ The engine's own reads/writes use the service-role client, which BYPASSES RLS** — so the basis is **resolved in application code** on **every** clinical read/write; RLS is necessary-but-not-sufficient for these paths (the RLS `has_clinical_relationship` predicate now mirrors the same basis — active_encounter / department_recent / break_glass). **Audit-on-READ** writes a row to the canonical **`clinical_phi_access_log`** (hospital, clinician, patient, **basis**, surface) **after** a successful authorised fetch — so a denied/failed read leaves no false "record read"; reads don't fire DB triggers.
3. **The clerkship is the documentation** (`lib/encounter/clerkship.ts`, pure, TDD). The structured Hutchison sections (history incl. SOCRATES + CAGE + systematic enquiry + Uganda always-asks + allergies; examination; synthesis incl. ranked differential with must-not-miss + problem list + justified investigations + management/disposition/safety-netting), **SOAP-mapped**, **structured-but-flexible** (every field optional; honest completeness; emergency-defer). `deriveClinicalObjects` fans the clerking out to the engine objects (no parallel store; no fabrication — blank entries dropped). `seedClerkshipFromTriage` makes the clerking a **continuation** of triage (PC + acuity + carried vitals), never a blank restart.
4. **Cadre-write rules** (`lib/encounter/access.ts`, INFERRED): a doctor/clinical-officer clerks; a **junior (intern) clerking is co-signed** (soft — diagnoses stay `working` until a senior attests); a nurse records allergies/observations but not a final medical diagnosis; reception writes nothing. Enforced in `recordClerkshipVersion`.
5. **Allergies → the prescribing check.** The clerking writes `patient_allergies` (the canonical table the prescribing allergy check is intended to read). **⚠️ HARD pre-launch dependency:** the prescribing engine **currently reads the resus-timeline allergy capture** (`lib/prescribing/administration.ts → recordedAllergiesFromTimeline`), **not** `patient_allergies`. Until it is pointed at the table, **clerked allergies silently do not gate prescribing** — so wiring the prescribing read to `patient_allergies` MUST land before this feature is turned on (tracked in Scope/deferred).
6. **Decision-support, not autonomous** — no auto-diagnosis; the clinician examines, reasons, decides. PHI free-text lives in `section_data` (encrypted at the app layer like other note bodies).

## Scope / deferred

- **Built — engine (GATE A–C):** the schema + GATED migration (0040) + RLS/access (legitimate-basis) + append-only + audit-on-read; the pure clerkship engine (sections, SOCRATES/CAGE, SOAP, derivation, completeness, triage seeding) + cadre rules + tests; the service-role write/read/audit orchestration; ICD-10/LOINC as versioned, sourced reference data (migration 0041).
- **Built — surfaces (GATE D):** the shared **longitudinal clinical record** panel (allergies-first) wired into the `/doctor` + `/nurse` patient pages; the per-encounter view + **append-only timeline** + the **clerkship documentation-entry form** (essential structured sections; ICD-10/LOINC pickers; draft/finalise) at `/doctor/encounters/[id]`; the **triage→encounter handoff** (`openEncounterFromTriage` + `startEncounterFromTriageAction`). All gated behind `ENCOUNTER_ENGINE_LIVE` so the branch deploys safe BEFORE the migration; the flag is flipped at apply time.
- **Launch sequence (GATE E):** (1) apply migrations 0040 + 0041 (`npm run db:migrate`); (2) **point the prescribing allergy read at `patient_allergies`** — the hard launch-blocker (see Decision §5), else clerked allergies don't gate prescribing; (3) set `ENCOUNTER_ENGINE_LIVE=1`; (4) merge → deploy.
- **Deferred (flagged, NOT built):** a "Start clerking" button on the shared triage desk (the handoff action exists; the button is a small role-aware wire-up); the clerkship form's **full** Hutchison structure (v1 ships the essential sections); particular-group flows (paediatric/obstetric/older/psychiatric/emergency/fever/pain) + system-specific exam templates; order **execution** + results ingestion; the care-team module (the `care_team` access basis is a documented seam); the **admission slice** (consumes the disposition).

## Consequences

**Positive:** a real, reviewable clinical-data spine AND its surfaces — `encounters` extended, the clinical objects defined with RLS + append-only + audit-on-read, the clerkship as structured/versioned documentation that populates the objects (no parallel store), triage continuity (the handoff seeds the clerking), cadre-scoped writes, the legitimate-access basis matching the doctor/nurse model, and the doctor/nurse surfaces wired — engine logic unit-tested, the whole branch building clean, gated behind a flag so it deploys before the migration. **Negative:** the surfaces can't be exercised end-to-end until 0040/0041 are applied + the flag is set (GATE E); the clerkship form ships the **essential** sections (not the full Hutchison structure) in v1; the prescribing→`patient_allergies` rewire is a hard prerequisite to turn-on; the `care_team` access basis remains a seam (always false until that module ships). The spec is now reconciled to the real kickoff (no longer inferred).
