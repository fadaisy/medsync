# ADR 0054 — Editable prescription parameters (the safety checks re-run on every edit)

**Status:** Accepted — CLINICAL-SAFETY artifact (the editable-parameters addendum to the smart prescribing tool, 2026-06-03)
**Context:** The catalog's doses are the guideline-correct _starting point_, not a fixed order — a prescriber legitimately tailors to the patient (renal dose-halving, a weight recalculation, a different route if IV access fails, an altered frequency/duration). The tool must support editing as a first-class action **without losing the safety net** — editing must never be a bypass. Built on the existing engine + records model (ADRs 0051–0052); the catalog and the core check logic are reused, not rewritten.

## Decision

1. **The engine re-runs the checks against the EDITED values.** `runSafetyChecks` now takes an optional `edit?: PrescriptionEdit` (`{ doseMg?, route?, concentration? }`) ([lib/prescribing/engine.ts](../../lib/prescribing/engine.ts)). The edited dose drives the **out-of-range** and **max/cumulative** checks; an edited route re-validates **concentration/route correctness**. When no edit is passed, behaviour is identical to before (the option list still uses the default-flag path).
2. **A new out-of-range / plausibility guard** (`dose_range`) compares the edited dose to the catalog reference (`unitDoseMg`): a normal clinical adjustment (~0.5–2×, e.g. renal dose-halving) raises **nothing**; further out (>2× / <0.5×) **warns**; far out (>3× / <0.34×) **blocks** (override + reason); egregiously out (≥5× / ≤0.2×) is `egregious` → the UI additionally requires a **typed dose confirmation**. It is **never a hard block** — a resus is time-critical; the clinician proceeds with an override + recorded reason. (Drugs without a numeric `unitDoseMg` reference — category-level — can't be range-checked; their dose stays free-text. This is flagged, not silently skipped.)
3. **The dialog edits inline with live re-checks** ([prescribe-dialog.tsx](../../app/nurse/resus/[episodeId]/_components/prescribe-dialog.tsx)): an "Adjust" expander exposes dose / route / concentration / frequency / duration / volume / rate / PRN / notes; `liveFlags = runSafetyChecks({…, edit})` is recomputed every render, so the flags update as values change. The **guideline default is shown alongside the edited value** (struck-through default), so deviation is visible, not hidden. Defaults stay one-tap-accept; editing is there when needed. Edits belong to the selected drug (`ed.drugId` guard) so switching option (hydrocortisone ↔ prednisolone) doesn't leak stale edits; the typed-confirm resets on option switch.
4. **The record is first-class edit history** ([recordEmergencyAdministration](../../app/nurse/resus/actions.ts)): the timeline `drug` event now stores the **edited values** (what is actually given + reconciled), the **guideline `default`**, the **field-level edit log** (`{field, from, to}[]`), and any **override reason + flags** — append-only/versioned, consistent with the immutable resus record. Controlled-drug edits keep the witness requirement.

## Consequences

**Positive:** the clinician tailors the prescription to the patient inside the tool (keeping the safety net + the record) instead of going around it; every edit re-runs the full check set; the out-of-range guard catches fat-finger/decimal errors (the atropine-0.5→10 class) while permitting legitimate adjustment; the deviation, the default, and the edits are all audited; the edited (not default) dose flows to the record + pharmacy reconciliation. **Negative:** the range guard is a ratio heuristic on `unitDoseMg` (not an explicit per-drug min/max) — sensible thresholds documented + CSO-ratifiable; category-level drugs (no numeric reference) get no dose-range check by design. Changing the thresholds is a traceable, CSO-authored change.
