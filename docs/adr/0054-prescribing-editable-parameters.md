# ADR 0054 — Editable prescription parameters (the safety checks re-run on every edit)

**Status:** Accepted — CLINICAL-SAFETY artifact (the editable-parameters addendum to the smart prescribing tool, 2026-06-03)
**Context:** The catalog's doses are the guideline-correct _starting point_, not a fixed order — a prescriber legitimately tailors to the patient (renal dose-halving, a weight recalculation, a different route if IV access fails, an altered frequency/duration). The tool must support editing as a first-class action **without losing the safety net** — editing must never be a bypass. Built on the existing engine + records model (ADRs 0051–0052); the catalog and the core check logic are reused, not rewritten.

## Decision

1. **The engine re-runs the checks against the EDITED values.** `runSafetyChecks` now takes an optional `edit?: PrescriptionEdit` (`{ doseMg?, route?, concentration? }`) ([lib/prescribing/engine.ts](../../lib/prescribing/engine.ts)). The edited dose drives the **out-of-range** and **max/cumulative** checks; an edited route re-validates **concentration/route correctness**. When no edit is passed, behaviour is identical to before (the option list still uses the default-flag path).
2. **A new out-of-range / plausibility guard** (`dose_range`) compares the edited dose to the catalog reference. Two reference shapes (a range takes precedence when both exist):
   - **`unitDoseMg`** (single-reference drugs): a ratio band around the standard dose — a normal clinical adjustment (~0.5–2×, e.g. renal dose-halving) raises **nothing**; further out (>2× / <0.5×) **warns**; far out (>3× / <0.34×) **blocks**; egregiously out (≥5× / ≤0.2×) is `egregious` → typed dose confirmation.
   - **`doseRangeMg` `{low, high}`** (added 2026-06-03 — fixed-regimen drugs with an escalating/ranged dose and no single reference: amiodarone 150/300, lidocaine 50/100, magnesium arrest 2 g, adenosine 6→18, salbutamol 2.5–10, ipratropium 0.25–0.5, prednisolone 40–50, magnesium asthma 1.2–2 g, TXA 1 g): a dose **inside [low, high]** raises **nothing**; **just outside** (≤1.5× the top / ≥⅔× the floor) **warns**; **further out** **blocks** (override + reason); **≥3× the top / ≤⅓× the floor** is `egregious` → typed confirmation. **Endpoints are derived from each entry's own already-web-verified fields — `adult.dose`/`adult.max`, plus `adult.interval` / the `paediatric` band where the plausible single-administration span is wider (e.g. salbutamol's 10 mg top is the "up to 10 mg/h" continuous rate; salbutamol 2.5 mg / ipratropium 250 µg lows are the paediatric band) — not a remembered number; each entry's comment names its endpoints. The band width is the CSO-ratifiable judgment.**
     It is **never a hard block** — a resus is time-critical; the clinician proceeds with an override + recorded reason. (Volume-dosed drugs — crystalloid mL, glucose mL — and pure category/record-only items, e.g. GTN, furosemide, vasopressor infusions, still have **no numeric mg guard** by design: a mg range doesn't apply to a mL/titrated order. This is the documented, narrowed gap — flagged, not silently skipped.)
3. **The dialog edits inline with live re-checks** ([prescribe-dialog.tsx](../../app/nurse/resus/[episodeId]/_components/prescribe-dialog.tsx)): an "Adjust" expander exposes dose / route / concentration / frequency / duration / volume / rate / PRN / notes; `liveFlags = runSafetyChecks({…, edit})` is recomputed every render, so the flags update as values change. The **guideline default is shown alongside the edited value** (struck-through default), so deviation is visible, not hidden. Defaults stay one-tap-accept; editing is there when needed. Edits belong to the selected drug (`ed.drugId` guard) so switching option (hydrocortisone ↔ prednisolone) doesn't leak stale edits; the typed-confirm resets on option switch.
4. **The record is first-class edit history** ([recordEmergencyAdministration](../../app/nurse/resus/actions.ts)): the timeline `drug` event now stores the **edited values** (what is actually given + reconciled), the **guideline `default`**, the **field-level edit log** (`{field, from, to}[]`), and any **override reason + flags** — append-only/versioned, consistent with the immutable resus record. Controlled-drug edits keep the witness requirement.

## Consequences

**Positive:** the clinician tailors the prescription to the patient inside the tool (keeping the safety net + the record) instead of going around it; every edit re-runs the full check set; the out-of-range guard catches fat-finger/decimal errors (the atropine-0.5→10 and amiodarone-300→3000 classes) while permitting legitimate adjustment; the deviation, the default, and the edits are all audited; the edited (not default) dose flows to the record + pharmacy reconciliation. The `doseRangeMg` addition (2026-06-03) closes the free-text gap for the **9 fixed-regimen drugs** that have a defined dose but no single `unitDoseMg` — they now get the numeric plausibility guard too, with the numeric mg input surfaced in the dialog. **Negative:** the guard is a heuristic — a ratio band on `unitDoseMg`, or relative distance outside `doseRangeMg` — not an explicit per-drug min/max with full pharmacological provenance; the endpoints are derived from each entry's verified dose string and the band widths/thresholds are CSO-ratifiable (they were not independently re-searched — a fresh web pass can be requested at sign-off). Volume-dosed (mL) and pure category/record-only drugs still get no mg range guard by design. Changing any range or threshold is a traceable, CSO-authored change.
