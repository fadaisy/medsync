# ADR 0058 — Resus vitals strip: previous→current + clinical trend arrow + hover trend graph

**Status:** Accepted — presentation/display artifact (2026-06-04). Surfaces the serial vitals the resus already records as a trajectory, where it matters most.
**Context:** The resus board's vitals strip showed the current value + a tiny sparkline — but **no previous value and no explicit trend direction**, and no way to inspect the trend without leaving the board. In a resus the **trajectory is the story** (a falling SpO₂, a climbing shock index, a dropping SBP). MedSync already holds the serial vitals (every "Record vitals" is timestamped; triage vitals carry in as the first reading) — this surfaces them. **Display only — vitals capture, the derived-metric maths, the interpretation thresholds, population routing, and the engine are all unchanged.**

## Decision

1. **One shared classifier is the single source** ([lib/resus/vital-trend.ts](../../lib/resus/vital-trend.ts), TDD — 12 tests). `vitalBand(key, value)` is the resus board's **existing** `vitalTone` cutoffs relocated **verbatim**, plus derived-metric bands that **reuse the triage scorer's existing thresholds** (`SHOCK_INDEX`, MAP ≥ 65). It drives the cell tone, the trend direction, and the graph reference bands — so they always agree. `vitalTone` in the desk now delegates to it (identical output). **No new thresholds invented.**
2. **The cell shows previous→current + a clinically-coloured arrow.** `vitalTrend(key, points)` reads the last two points of the already-recorded series: `rawDirection` (↑/↓/→ — the glyph) is the numeric move; **`clinicalDirection` (the colour) is by clinical meaning**: a band change = improving (better band, teal) / deteriorating (worse band, rose); **within an unchanged _non-normal_ band, movement toward the failing danger edge = deteriorating and away = improving** (so a still-critical SBP 85→80 reads deteriorating, not a calm neutral); within normal = neutral (muted). So a **rising SpO₂ reads as improving and a falling SpO₂ as deteriorating** — by clinical meaning, not raw direction. The cell background keeps the **current band tone** (where it is) while the arrow shows **which way + good/bad**. Fine-grained metrics (shock index) show 2 dp + a 2-dp delta. Colour **+** glyph **+** value (never colour alone); an aria-label (`vitalTrendLabel`) gives screen-reader users the same trend; the arrow appears only with **≥ 2 readings** (honest single-reading state).
3. **Hover/tap reveals a clean trend graph** (`VitalTrendGraph`): an SVG line over the resus with the **clinical-normal band shaded** + **danger thresholds** dashed (from the same `vitalBand` cutoffs — `VITAL_REFERENCE`, respecting scores-0-≠-normal since these are the clinical cutoffs, not NEWS2-0); a **time-aware x-axis** (points plotted at their actual reading times, irregular intervals honest); the latest point emphasised. **BP is shown as a pair** — SBP primary + DBP secondary two-line. The self-contained derived metrics (**shock index, MAP**) plot the existing derived series the same way. Reduced-motion-safe (it appears without animation); the popover toggles on **tap** for touch (not hover-only). **Pulse pressure + qSOFA stay flag-toned chips** (no continuous trend graph): pulse pressure because its "narrow" interpretation is **SBP-relative** (a context-free pulse-pressure band would silently drop that occult-shock/tamponade signal), qSOFA because it is a categorical 0–3 score.
4. **Read-model only** ([lib/resus/vitals.ts](../../lib/resus/vitals.ts)): the existing shock-index + MAP derived series are plotted; nothing in the derived maths changes.

## Consequences

**Positive:** the team reads, per vital, where it was, where it is, which way it's moving, and whether that's good or bad — at a glance — and can inspect the full trajectory against the normal band without leaving the board; the trend (MedSync's genuine edge — it holds serial vitals most ED triage doesn't) is surfaced where it matters most. One classifier keeps cell/arrow/graph consistent. **Negative:** DBP/EtCO₂ have no existing danger band, so their movement is always neutral (we don't invent thresholds); pulse pressure stays a flag-toned chip (no line graph) because its band is SBP-relative. A future enhancement could add population-routed (paeds/obstetric) bands by routing `vitalBand` through the triage interpret engine — deferred (the resus board's existing classification is adult-cutoff; unchanged here).

## Guardrails honoured

Vitals capture, `computeDerivedMetrics` + all `lib/triage/scoring/*` maths, the interpretation thresholds (`constants.ts`), population routing, the resus engine, findings→action, and the immutable record are **byte-for-byte unchanged**. Real data only — no fabricated previous/trend; honest single-reading + missing states. No migration touched.
