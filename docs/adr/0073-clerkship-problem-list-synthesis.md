# ADR-0073 — Clerkship Problem-List Synthesis (reasoned problems-with-evidence)

**Status:** Accepted (GATE A clinical model CSO-signed 2026-06-14; gates B+C run together under "deploy the final product"). Built on `feat/problem-list-synthesis`. **Supersedes** the problem-list portion of the Assessment/Synthesis model ([ADR 0066 region] / the eligibility-correction's "one line per abnormal vital" display).

**Context:** `clerkship-problem-list-synthesis-kickoff.md`. The proposed problem list listed each raw abnormal vital as its own problem (a data dump). The rework makes it **reason across symptoms + signs + risks + abnormal vitals into the most-likely PROBLEMS/working diagnoses, each carrying its supporting evidence underneath**. Grounded in a 5-reader code-mapping fan-out; the decisive finding was that the **reasoning engine already carries per-hypothesis evidence but is vitals-blind**. **No migration** — `ClerkProblem.evidence: string[]` rides the versioned `section_data`; the `problem_list` projection is unaffected.

## Decision

1. **The synthesised problem IS the reasoning engine's leading hypothesis — not a second diagnosis-engine.** `synthesiseProblemList()` (`lib/clerkship/problem-synthesis.ts`, pure, TDD) reads the engine's `ScoredDifferential[]`, takes the `status === "supported"` items, and reuses their **own** evidence buckets verbatim — `matchedRuleIn` (symptoms) · `supportPresent` (signs) · `riskPresent` (risk factors) — nesting them under the problem. It never re-scores, re-ranks, or invents a diagnosis.
2. **Honest hypothesis wording (CSO Q2):** headline `likely {dx} (working)` + a status chip (`must-not-miss` reserved-red / `supported`). Never asserted as a confirmed diagnosis; the persisted `item` is the dx (the hedge is display-only).
3. **Abnormal-vital safety net (CSO Q1 — conservative, clinician-confirmed):** the engine is vitals-blind, so a vital is absorbed as evidence **only** when its body system matches one the hypothesis already draws support from — the differential's own `supportingSymptoms[].system` (CSO-signed map data) crossed with a **tiny vital→system map** (the only new reference data: SpO₂/RR→respiratory, HR/BP→cardiovascular, glucose→endocrine, GCS→neurological; **temperature deliberately unmapped** — fever is non-specific). Default is **standalone**. The absorption diagnoses nothing — it only attaches an already-abnormal vital to an already-supported hypothesis.
4. **No abnormal vital is ever dropped.** A vital ends in exactly one place: nested under a shown synthesised problem, carried as evidence under an already-confirmed problem, or surfaced **standalone** ("unexplained · for review"). Excluding a hypothesis returns its vitals to standalone; confirming it carries them as evidence and removes them from standalone (reactive recompute from the excluded/confirmed sets).
5. **Reconciliation — one coherent record, never two disagreeing surfaces.** Confirming a synthesised problem = **agreeing the differential** (`onAgree`) **and** committing it as a problem-with-evidence (`onConfirmProblem`); rejecting = `onExclude` ("considered & excluded", must-not-miss retained). After a decision the dx is actionable in exactly one zone.
6. **Still proposed; the clinician decides.** Findings + active background remain proposed on their own terms; confirmed problems keep active/resolved/**link-under-a-diagnosis**; nothing silently removed.

## Consequences

- The Assessment Zone 3 is now "Problem list — synthesised": likely problems-with-evidence, then unexplained standalone vitals, then other (finding/background) proposals, then the confirmed list (evidence shown nested). Decision-support, never autonomous; real data only.
- **Pre-deploy adversarial review (7 agents) caught a real defect** before production: `ClerkProblem.evidence` was threaded through the type/zod/server-mapper but not the two form-state boundary sites, so it was dropped on save+reload — which could resurface an absorbed vital as standalone (a "no vital dropped" breach). Fixed + locked with a `clerkshipInputToClerkship` round-trip regression test.
- **Open follow-up:** the vital→system map is coarse and the dx's systems come only from `supportingSymptoms` (a differential with none absorbs no vitals — the safe default). Richer vital-aware reasoning (feeding vitals into the engine + map vital-signatures) was rejected here as too high-blast-radius (it would change the rail's ranking and need re-signing all 17 maps).
