# NCDSync build decisions

Choices the build prompt leaves open, one line of rationale each (§2.5). Deviations from the prompt are marked **DEV**.

| Id   | Decision                                                                                                                                                                                                                                                                                                                                                                        | Rationale                                                                                                                                                                                                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | Module root `lib/ncdreg/`, routes `app/ncd/`, tests `tests/ncdreg/`.                                                                                                                                                                                                                                                                                                            | `lib/ncd/` already holds the consultation decision-support engine; a separate root keeps the §5.6 condition-code search meaningful and avoids collisions with `feat/ncd-diabetes-pack`.                                                                                                              |
| D-02 | **DEV** npm, not pnpm; Node 24 present (prompt says 22).                                                                                                                                                                                                                                                                                                                        | The repository uses npm; the repo wins.                                                                                                                                                                                                                                                              |
| D-03 | **DEV** `ncd_person` holds the registry person with encrypted identifiers and nullable link columns `patient_user_id` (→ `patient_profiles`) and `provisional_patient_id` (→ `provisional_patients`), never set for a synthetic person.                                                                                                                                         | `patient_profiles` requires an auth account per patient (the demo must create no accounts) and `provisional_patients` is the hospital-wide desk queue fed to identity reconciliation; registry persons (and every demo person) must not surface there. Linking is the seam for reconciliation later. |
| D-04 | **DEV** Minimal `ncd_appointment` (day-level) instead of `appointments`.                                                                                                                                                                                                                                                                                                        | The scheduling engine books clinician slots through Edge Functions; registry next-visit dates are day-level, and demo appointments must not appear on reception or doctor calendars. Seam documented in ADR 0209.                                                                                    |
| D-05 | Indicators are pure functions over a facility dataset loaded in one read, not SQL views; a monthly `ncd_indicator_snapshot` stores results.                                                                                                                                                                                                                                     | One tested implementation for golden dataset, live views and snapshots; PGlite and production run the same code; timings measured on 2,000 patients.                                                                                                                                                 |
| D-06 | Live views compute with the as-of date = today and the same calendar-month windows (the reporting month is the current month).                                                                                                                                                                                                                                                  | One window rule for snapshots and live views; matches HEARTS360's month logic.                                                                                                                                                                                                                       |
| D-07 | Care-band "ulcer or amputation" also counts `foot_ulcer_new`, `amputation_minor`, `amputation_major` events, not only foot-review fields.                                                                                                                                                                                                                                       | An event recorded by the ward is the same fact as a review finding.                                                                                                                                                                                                                                  |
| D-08 | Retinopathy grade `ungradable` does not count as "retinopathy of any grade".                                                                                                                                                                                                                                                                                                    | Ungradable is not a finding of retinopathy.                                                                                                                                                                                                                                                          |
| D-09 | Name similarity: names normalised (lower case, accents and punctuation stripped, doubled letters collapsed, a final `h` dropped), blind-indexed per token; "similar name" = some token pair with Jaro-Winkler ≥ 0.90.                                                                                                                                                           | Token-order-insensitive, no English phonetics; retrieves `Nakatto`/`Nakato` and `Aminah`/`Amina` by index, and lands every `duplicate_check_demo` candidate in its tier. Draft, on the sign-off register.                                                                                            |
| D-10 | NCD roles: derived from the repo's roles and cadres (nurse cadres → triage nurse; doctor cadres and clinical officer → clinician; RECEPTION cadre → registry officer; `hospital_admin` → administrator), plus explicit per-facility assignments in `ncd_staff_role` for registry lead, head of department, auditor and clinical safety officer, which the repo has no role for. | §7 I1: map onto existing roles; only roles the repository lacks get an assignment row.                                                                                                                                                                                                               |
| D-11 | Clinical safety approval capability: held by nobody by default; an assignment row `clinical_safety_officer` can only be written by the database owner (no UI, no app path).                                                                                                                                                                                                     | §7 I1 and §14: the repo has no CSO role.                                                                                                                                                                                                                                                             |
| D-12 | View, drill-down, export, reveal and sign events go to an append-only `ncd_access_event` table that carries `audit_log_changes()`, so each also lands in `audit_log`.                                                                                                                                                                                                           | `audit_log` accepts insert/update/delete only and is trigger-written; this routes views through it unchanged.                                                                                                                                                                                        |
| D-13 | Parish is free text beside village (both encrypted); district and sub-county are dataset ids.                                                                                                                                                                                                                                                                                   | The geography dataset stops at sub-county (sign-off register).                                                                                                                                                                                                                                       |
| D-14 | The capability map is one global reference table `ncd_capability_grant` (no `facility_id`), seeded from `lib/ncdreg/capabilities.ts`.                                                                                                                                                                                                                                           | It is configuration of the standard, not facility data; a test holds it equal to the code.                                                                                                                                                                                                           |
| D-15 | The registry lead also holds `aggregate_view` and `report_view`.                                                                                                                                                                                                                                                                                                                | A report cannot be signed by someone who cannot read it.                                                                                                                                                                                                                                             |
| D-16 | The hospital administrator holds `ncd_role_assign` (registry lead, head of department, auditor), never the CSO role.                                                                                                                                                                                                                                                            | Someone at the facility must be able to assign the roles the repository lacks; the CSO stays owner-only (D-11).                                                                                                                                                                                      |
| D-17 | Blind indexes reuse `lib/encryption.ts#blindIndex` (key derived from the PHI key) with NCD domain prefixes (`ncd-name:`, `ncd-phone:`, `ncd-hosp:`, `ncd-nin:`).                                                                                                                                                                                                                | §7 A: follow the repository's existing search approach; the derived key is already separate from the encryption key.                                                                                                                                                                                 |
| D-18 | A closing disposition (`transfer_out`, `discharged_to_primary_care`) also records a `transfer_out` event dated the visit day.                                                                                                                                                                                                                                                   | Patient status is computed from events; discharge to primary care leaves the registry's care the same way.                                                                                                                                                                                           |
| D-19 | Demo removal and "Remove all synthetic records" run as the `demo_loader` principal; no human role can delete any row.                                                                                                                                                                                                                                                           | Keeps `demo_data_manage` (held by the administrator) from granting read access to real persons.                                                                                                                                                                                                      |
| D-20 | Reminders are scheduled rows created with each appointment (one before, N after a miss) and re-checked at send time.                                                                                                                                                                                                                                                            | D1 asks to cancel pending reminders at once; scheduled rows make that observable (catalogue `reminders_pending: 0`).                                                                                                                                                                                 |
| D-21 | Hand-entered synthetic persons get `DEMO-M-<8 hex>` numbers; demo-loaded ones keep the catalogue's `DEMO-` numbers.                                                                                                                                                                                                                                                             | The live sequence never issues the DEMO- series (§8.3).                                                                                                                                                                                                                                              |
| D-22 | `will_return` with a date records the promised date on the call; it books no appointment and the patient stays overdue until a visit. | The demo catalogue keeps VM on the recall list after a will-return call (8 overdue) and the preview shows "Will return · 08 Oct" on an overdue row. Golden C13 re-derived for R10. |
