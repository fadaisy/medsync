# NCDSync build decisions

Choices the build prompt leaves open, one line of rationale each (§2.5). Deviations from the prompt are marked **DEV**.

| Id   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Rationale                                                                                                                                                                                                                                                                                                                |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D-01 | Module root `lib/ncdreg/`, routes `app/ncd/`, tests `tests/ncdreg/`.                                                                                                                                                                                                                                                                                                                                                                                                                                       | `lib/ncd/` already holds the consultation decision-support engine; a separate root keeps the §5.6 condition-code search meaningful and avoids collisions with `feat/ncd-diabetes-pack`.                                                                                                                                  |
| D-02 | **DEV** npm, not pnpm; Node 24 present (prompt says 22).                                                                                                                                                                                                                                                                                                                                                                                                                                                   | The repository uses npm; the repo wins.                                                                                                                                                                                                                                                                                  |
| D-03 | **DEV** `ncd_person` holds the registry person with encrypted identifiers and nullable link columns `patient_user_id` (→ `patient_profiles`) and `provisional_patient_id` (→ `provisional_patients`), never set for a synthetic person.                                                                                                                                                                                                                                                                    | `patient_profiles` requires an auth account per patient (the demo must create no accounts) and `provisional_patients` is the hospital-wide desk queue fed to identity reconciliation; registry persons (and every demo person) must not surface there. Linking is the seam for reconciliation later.                     |
| D-04 | **DEV** Minimal `ncd_appointment` (day-level) instead of `appointments`.                                                                                                                                                                                                                                                                                                                                                                                                                                   | The scheduling engine books clinician slots through Edge Functions; registry next-visit dates are day-level, and demo appointments must not appear on reception or doctor calendars. Seam documented in ADR 0210.                                                                                                        |
| D-05 | Indicators are pure functions over a facility dataset loaded in one read, not SQL views; a monthly `ncd_indicator_snapshot` stores results.                                                                                                                                                                                                                                                                                                                                                                | One tested implementation for golden dataset, live views and snapshots; PGlite and production run the same code; timings measured on 2,000 patients.                                                                                                                                                                     |
| D-06 | Live views compute with the as-of date = today and the same calendar-month windows (the reporting month is the current month).                                                                                                                                                                                                                                                                                                                                                                             | One window rule for snapshots and live views; matches HEARTS360's month logic.                                                                                                                                                                                                                                           |
| D-07 | Care-band "ulcer or amputation" also counts `foot_ulcer_new`, `amputation_minor`, `amputation_major` events, not only foot-review fields.                                                                                                                                                                                                                                                                                                                                                                  | An event recorded by the ward is the same fact as a review finding.                                                                                                                                                                                                                                                      |
| D-08 | Retinopathy grade `ungradable` does not count as "retinopathy of any grade".                                                                                                                                                                                                                                                                                                                                                                                                                               | Ungradable is not a finding of retinopathy.                                                                                                                                                                                                                                                                              |
| D-09 | Name similarity: names normalised (lower case, accents and punctuation stripped, doubled letters collapsed, a final `h` dropped), blind-indexed per token; "similar name" = some token pair with Jaro-Winkler ≥ 0.90.                                                                                                                                                                                                                                                                                      | Token-order-insensitive, no English phonetics; retrieves `Nakatto`/`Nakato` and `Aminah`/`Amina` by index, and lands every `duplicate_check_demo` candidate in its tier. Draft, on the sign-off register.                                                                                                                |
| D-10 | NCD roles: derived from the repo's roles and cadres (nurse cadres → triage nurse; doctor cadres and clinical officer → clinician; RECEPTION cadre → registry officer; `hospital_admin` → administrator), plus explicit per-facility assignments in `ncd_staff_role` for registry lead, head of department, auditor and clinical safety officer, which the repo has no role for.                                                                                                                            | §7 I1: map onto existing roles; only roles the repository lacks get an assignment row.                                                                                                                                                                                                                                   |
| D-11 | Clinical safety approval capability: held by nobody by default; an assignment row `clinical_safety_officer` can only be written by the database owner (no UI, no app path).                                                                                                                                                                                                                                                                                                                                | §7 I1 and §14: the repo has no CSO role.                                                                                                                                                                                                                                                                                 |
| D-12 | View, drill-down, export, reveal and sign events go to an append-only `ncd_access_event` table that carries `audit_log_changes()`, so each also lands in `audit_log`.                                                                                                                                                                                                                                                                                                                                      | `audit_log` accepts insert/update/delete only and is trigger-written; this routes views through it unchanged.                                                                                                                                                                                                            |
| D-13 | Parish is free text beside village (both encrypted); district and sub-county are dataset ids.                                                                                                                                                                                                                                                                                                                                                                                                              | The geography dataset stops at sub-county (sign-off register).                                                                                                                                                                                                                                                           |
| D-14 | The capability map is one global reference table `ncd_capability_grant` (no `facility_id`), seeded from `lib/ncdreg/capabilities.ts`.                                                                                                                                                                                                                                                                                                                                                                      | It is configuration of the standard, not facility data; a test holds it equal to the code.                                                                                                                                                                                                                               |
| D-15 | The registry lead also holds `aggregate_view` and `report_view`.                                                                                                                                                                                                                                                                                                                                                                                                                                           | A report cannot be signed by someone who cannot read it.                                                                                                                                                                                                                                                                 |
| D-16 | The hospital administrator holds `ncd_role_assign` (registry lead, head of department, auditor), never the CSO role.                                                                                                                                                                                                                                                                                                                                                                                       | Someone at the facility must be able to assign the roles the repository lacks; the CSO stays owner-only (D-11).                                                                                                                                                                                                          |
| D-17 | Blind indexes reuse `lib/encryption.ts#blindIndex` (key derived from the PHI key) with NCD domain prefixes (`ncd-name:`, `ncd-phone:`, `ncd-hosp:`, `ncd-nin:`).                                                                                                                                                                                                                                                                                                                                           | §7 A: follow the repository's existing search approach; the derived key is already separate from the encryption key.                                                                                                                                                                                                     |
| D-18 | A closing disposition (`transfer_out`, `discharged_to_primary_care`) also records a `transfer_out` event dated the visit day.                                                                                                                                                                                                                                                                                                                                                                              | Patient status is computed from events; discharge to primary care leaves the registry's care the same way.                                                                                                                                                                                                               |
| D-19 | Demo removal and "Remove all synthetic records" run as the `demo_loader` principal; no human role can delete any row.                                                                                                                                                                                                                                                                                                                                                                                      | Keeps `demo_data_manage` (held by the administrator) from granting read access to real persons.                                                                                                                                                                                                                          |
| D-20 | Reminders are scheduled rows created with each appointment (one before, N after a miss) and re-checked at send time.                                                                                                                                                                                                                                                                                                                                                                                       | D1 asks to cancel pending reminders at once; scheduled rows make that observable (catalogue `reminders_pending: 0`).                                                                                                                                                                                                     |
| D-21 | Hand-entered synthetic persons get `DEMO-M-<8 hex>` numbers; demo-loaded ones keep the catalogue's `DEMO-` numbers.                                                                                                                                                                                                                                                                                                                                                                                        | The live sequence never issues the DEMO- series (§8.3).                                                                                                                                                                                                                                                                  |
| D-22 | `will_return` with a date records the promised date on the call; it books no appointment and the patient stays overdue until a visit.                                                                                                                                                                                                                                                                                                                                                                      | The demo catalogue keeps VM on the recall list after a will-return call (8 overdue) and the preview shows "Will return · 08 Oct" on an overdue row. Golden C13 re-derived for R10.                                                                                                                                       |
| D-23 | The dashboard, drill-down and monthly-report choices are recorded in `docs/ncd/lanes/B.md`; recall, SMS, reviews-due, my-patients and data-quality choices in `docs/ncd/lanes/C.md`.                                                                                                                                                                                                                                                                                                                       | Two parallel build lanes (§2.7); each kept its decisions beside its code.                                                                                                                                                                                                                                                |
| D-24 | The NCD service worker (`public/ncd-sw.js`, scope `/ncd`) caches only a static offline shell (`/ncd-offline`) and content-hashed build assets; patient data for offline work lives only in the encrypted IndexedDB cache.                                                                                                                                                                                                                                                                                  | Extends ADR 0088 without breaking it: no cached page carries patient data.                                                                                                                                                                                                                                               |
| D-25 | FHIR R4 structure is validated in tests with Zod schemas of the required elements of the five resources, not an official validator.                                                                                                                                                                                                                                                                                                                                                                        | The official validator needs Java or a network service (HARD STOP 1/2).                                                                                                                                                                                                                                                  |
| D-26 | Calibration was tuned on an in-memory mirror of the writer and loader; the gate run loads through the real command path. After five rounds the best-scoring configuration (round 4) was kept.                                                                                                                                                                                                                                                                                                              | Each database load takes about an hour on this machine; §10.4 limits tuning to five rounds.                                                                                                                                                                                                                              |
| D-27 | A legacy import row must carry a next appointment date; a blank one is a dry-run error, not an implied discharge.                                                                                                                                                                                                                                                                                                                                                                                          | A discharge would record a transfer event and end active follow-up.                                                                                                                                                                                                                                                      |
| D-28 | Offline entries the server refuses for a reason a person must settle (values to confirm, possible duplicates, a conflict) are held on the device, encrypted, and block only that patient's later entries; they are released with the confirmation or discarded deliberately with a note. Only refusals that can never succeed (invalid, forbidden, not found, interlock) are discarded automatically.                                                                                                      | P11 review finding 5: discarding a confirmation request lost a nurse's measurements.                                                                                                                                                                                                                                     |
| D-29 | Measurements that arrive after the clinician closed the visit are kept and versioned; the visit stays closed. Every nurse and clinician re-save keeps the earlier values in `ncd_record_version`.                                                                                                                                                                                                                                                                                                          | P11 review findings 5 and 15 (G2): an offline save must never be refused for arriving late.                                                                                                                                                                                                                              |
| D-30 | A search token is bound to the name tokens searched (blind-indexed), as well as to the user, facility, principal and time.                                                                                                                                                                                                                                                                                                                                                                                 | P11 review finding 15: one token unlocked any number of enrolments of other names.                                                                                                                                                                                                                                       |
| D-31 | Interlock 6 keys on "any synthetic person exists, or demo data is active", not on the demo load alone. Exports (DHIS2, FHIR, research) therefore never run before go-live.                                                                                                                                                                                                                                                                                                                                 | P11 review finding 12: hand-entered synthetic persons reached real-format exports.                                                                                                                                                                                                                                       |
| D-32 | The legacy import runs in one transaction (each command a savepoint) and confirms out-of-range values only when the user accepts the dry run's list of them; the dry run also tiers patients within the same file against each other.                                                                                                                                                                                                                                                                      | P11 review finding 13: a half-applied import and blanket confirmations.                                                                                                                                                                                                                                                  |
| D-33 | The offline read copy expires 72 hours after it was fetched (removed on read).                                                                                                                                                                                                                                                                                                                                                                                                                             | P11 review finding 14: a lost phone kept the clinic list indefinitely. 72 hours covers a weekend without a connection.                                                                                                                                                                                                   |
| D-34 | Indicator inputs are read in a fixed order and same-day ties go to the later-entered record, then the id.                                                                                                                                                                                                                                                                                                                                                                                                  | P11 review finding 9: two closed visits on one date made C04/C05 depend on heap order.                                                                                                                                                                                                                                   |
| D-35 | The aggregate CSV applies the screen's small-count rule: counts from 1 to 4 read "1–4" for a role without drill-down.                                                                                                                                                                                                                                                                                                                                                                                      | P11 review finding 15 (F6).                                                                                                                                                                                                                                                                                              |
| D-36 | A superadmin holds only NCD roles assigned explicitly at that hospital (migration 0094, ADR 0215); derived roles still never apply to a superadmin.                                                                                                                                                                                                                                                                                                                                                        | Owner decision 2026-10-06: the owner is both superadmin and CSO and uses one account. Platform access alone still opens nothing.                                                                                                                                                                                         |
| D-37 | Outcomes by condition is a list and detail view: every enabled condition in a rail (share, meter, sparkline, under care; ordered by G02) and the selected one at full size (figure, G04 distribution with counts, care cascade, 12-month trend with month labels, on the shared scale). The conditions card has a 30rem floor, so the dashboard may scroll on screens shorter than 1440×1000 instead of squeezing it.                                                                                      | Owner request 2026-10-08: the four-across rows were too small. Departs from §11.3 item 8's row layout and F7's never-scroll rule; one row per condition, the shared scale and every figure from the engine are kept.                                                                                                     |
| D-38 | The selected condition's charts are three linked modules (trend, outcome breakdown, care cascade), each with a Chart / Table switch. Pointing at or stepping through a month on the trend (crosshair, tooltip, keyboard slider) redraws the breakdown and cascade for that month, with the change in points against the month before and the drop between cascade steps. Compare overlays the other conditions as grey context lines; the one pointed at is emphasised by weight, dash and a direct label. | Owner request 2026-10-08 for smarter, modular, interactive charts. No categorical palette: every combination of the cool hues failed the CVD and normal-vision checks of the dataviz validator, so comparison is by emphasis, not hue. Monthly slices sent to the browser carry hidden counts as text only (F6, tested). |
