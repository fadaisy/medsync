# Examination token map: summary (Phase 0, Q5)

**Input:** MS-EMR-EXAM-CAT-001 1.0.0-draft, mapped against the CFC concepts in `lib/facts/catalogue.generated.ts` (CFC v1 and v1.1).

**Output:** `exam-token-map.csv`, 270 rows: 149 items, 90 option- or attribute-level findings, 14 block rows (consciousness, AMTS, motor grids, pulses grid) and 17 vital-sign rows (14 fields, 3 panels).

**Status:** a proposal for GATE A. Every concept marked `matched`, `broader` or `vital` exists in `catalogue.generated.ts` (checked by script). None is invented.

## 1. How it was decided (the history build's rules)

- **Resolution.** `conceptForToken` (`lib/emr/write/notes.ts`) accepts a CFC concept id of kind `finding` or `observation`, or a `symptom_catalog` code resolved through the concept that carries it as `symptomCode`. Examination rows name CFC ids directly.
- **The symptom catalogue is not used for examination signs.** No new `symptom_catalog` code is needed.
  - Where a symptom token means the same as the sign, the examination reuses it with `elicitedBy=examination`, as the CFC already does for `sign.jaundice` and `sign.oedema`. Twelve such concepts exist only in the unadopted history addendum (`cfc-v1.2-proposal.json`); they are reused, not duplicated (section 4).
  - Where the symptom token is a broader screen of the history (`eye_symptoms`, `noisy_breathing`, `abdominal_distension`, `easy_bruising_bleeding`, `gait_disturbance`, `rectal_bleeding`, `sx.scrotal`), the sign gets its own concept (the `sign.pallor` precedent).
- **One concept per answerable item.**
  - `presence` and `test` items, and `state` items whose positive state is a named sign ("JVP raised", "trachea deviated"), map to `sign.<snake>` (a presence finding).
  - `state` items for a structure (mouth, heart sounds, cranial nerves, fundi) and `choice` items map to `exam.<snake>`, a coded observation, following `exam.monofilament`.
  - `device` items and the oxygen modality map to new `dev.<snake>` "device in situ" findings. The CFC has no device concepts.
- **Why the `sign.*` / `exam.*` split matters.** The read contract projects only `elicitedBy`, `onset`, `durationDays`, `severity` and `laterality` for a presence finding (`FindingFactSchema`, `FINDING_KEYS`). For an observation it projects `context.qualifiers`. Option ids on a `sign.*` fact are stored but **invisible to engines**; on an `exam.*` observation they are readable.
- **Option-level rows** exist only when: an existing CFC concept is that finding; a flag or classifier reads it under a `sign.*` item; the same finding is recorded in two items; a symptom token with the same meaning exists; it is a device inside a non-device item; or it is not a finding. Descriptors (side, degree, grade, site, size, consistency, timing) stay qualifiers.
- **Direction.** `broader` only where the CFC concept is the superset (section 6).

## 3. Missing observation context (existing concepts)

- **`obs.avpu`:** no answer for C (new confusion). Extend the answers.
- **GCS:** only the total. "E3 VNT M6" writes nothing; hence `obs.gcs_eye`, `obs.gcs_verbal`, `obs.gcs_motor`.
- **`obs.spo2`:** air or oxygen is its context `oxygenSupport`. The NEWS2 scale, the 88–92% target, FiO₂ and PEEP have no context key.
- **Blood pressure:** `lying` is written `supine`; cuff `standard_adult` → `adult`, but `small_adult_or_child` cannot map (the CFC splits `small_adult | child`); `device`, `setting`, `readingSetId` and `readingIndex` are required and not asked; the minutes after standing have no key.
- **`obs.temperature`:** site has no key (a qualifier).
- **Required context never captured** (stored but non-interpretable, law C2): `obs.capillary_refill` needs `site`; `obs.waist` needs `protocol`.
- **`obs.heart_rate`:** rhythm and the apex-radial deficit have no key.
- **`obs.glucose`:** `specimen=capillary_whole_blood`; random → `non_fasting`; two hours after food → `non_fasting` + `challenge: meal`, 120 minutes.
- **MUAC, weight, height:** direct. "Stated" → `measurement: reported`.

## 5. Sensitivity mismatches

A fact is restricted if its concept is restricted **or** its line says so (`sensitivityFor(concept, line.restricted)`). The examination commit sets the line from the catalogue item, as the history commit does. Open cases:

1. The restricted HIV-associated signs item mirrors five options owned by standard items (oral thrush, angular cheilitis, Kaposi-like lesion in the mouth, Kaposi and zoster scars in skin, generalised nodes). A mirror is one fact written by the owner at the owner's sensitivity (standard). The WHO stage hint never travels into it.
2. **Kaposi-like lesion** is proposed restricted, but the standard mouth and skin items record it, so their text would show it to patients unless it is treated as restricted there. CSO decision.
3. Duplicates without a declared mirror, written at two sensitivities: `hiv_associated_signs:recurrent_oral_ulcers` / `mouth:ulcers`, and `hiv_associated_signs:fungal_nail_infection` / `feet.skin_nails:fungal_nails`. Declare them as mirrors.
4. `ex.abdomen.liver_stigmata:testicular_atrophy` is a genital finding in a standard item outside the gate. CSO decision.
5. `ex.nervous.behaviour:responding_to_unseen_stimuli` sits in a standard item but maps to a restricted (mental health) concept. CSO decision.
6. Scrotal findings are standard in the history (`sym.scrotal`) and restricted in the examination. Align the catalogues.
7. Consistent: external genitalia (restricted), prostate (standard; the gate is not a restricted class); no existing CFC concept used here is restricted.
8. Four new restricted concepts: `sign.hiv_associated_signs`, `sign.kaposi_like_lesion` (CSO to confirm), `exam.external_genitalia`, `exam.scrotum_testes`.

## 7. Other findings for the build

- **Findings recorded twice with no mirror declared** (the E-8 risk): splinter haemorrhages, malar flush, papilloedema, field defect, bruising, fresh blood per rectum, haematuria, bilateral pitting oedema, chest drain, stoma, irregular rhythm, tachypnoea, renal bruits. The commit merges per concept: present if any source is present, absent only if every recorded source is absent.
- **Laterality required:** `sign.foot_ulcer`, `sign.foot_infection`, `sign.foot_deformity`, `sign.foot_callus`, `sign.gangrene`, `exam.pedal_pulses`, `exam.monofilament`, `exam.vibration_128hz`, `exam.ankle_reflex`. A negative answer writes one fact per side, or `bilateral`. `ex.feet.skin_nails` has no side attribute: add one.
- **Derived results:** `sign.dehydration` and `sign.foot_infection` come from their classifiers with inputs and rule version. GTFCC "below threshold" and "not graded" write no fact, never `none`. Foot infection needs two or more local signs, never one ticked sign. The hypoglycaemia level maps to `evt.hypoglycaemia`. The other results (IMAM, BMI, waist, WHtR, CRB65, ROSIER, GCS-P, orthostatic, inter-arm, asthma, IWGDF risk, SINBAD) need derived concepts.
- **Conditions** (`cond.amputation_history`) go through the problem-list path (`recordProblem`), not the finding path.
- **Not a finding:** `fundoscopy:not_visualised` belongs in `not_examined`.
- **No airway item:** a tracheostomy without ventilation cannot be recorded.
