# CFC addendum v1.4: three history findings of the right breadth (proposal for the CSO)

**Status: awaiting CSO signature.** Nothing is built. Signed on 2026-09-28 as a direction (legacy conversion §5,
`docs/emr/clerking-v2/legacy-conversion-proposal.md` §7): the three catalogue symptoms that still chart as a
narrower concept get concepts of their own breadth, in an addendum like v1.2 and v1.3 (ADR 0176).

## The problem

At signing, a catalogue symptom charts as its token's concept (`data/clerking/token-map.v1.json`). CFC v1.2 (M1)
fixed vaginal bleeding, falls and periods change. Three rows still send a **broader** symptom to a **narrower**
concept, so a signed note can assert a detail nobody recorded:

| Catalogue symptom                          | Its options                                                 | Charts today as                                                                               | What goes wrong                                                                                         |
| ------------------------------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `sym.nausea_vomiting` "Nausea or vomiting" | onset, times, content, relation, projectile, keeping fluids | `sx.vomiting` "Vomiting" (code `vomiting`)                                                    | Nausea alone is charted as vomiting. No option says "nausea only", so the qualifiers cannot recover it. |
| `sym.blurred_vision` "Change in vision"    | eye, type ∈ blurred/double/loss/field/flashes, pain         | `sx.blurred_vision` "Blurred vision"                                                          | Loss of vision is charted as blurred vision. The `type` qualifier holds the truth.                      |
| `sym.claudication` "Leg pain on walking"   | site ∈ calf/thigh/buttock, distance, rest_pain              | `sx.claudication` "Calf pain on walking, relieved by rest" (code `intermittent_claudication`) | Thigh or buttock pain, or pain at rest, is charted as calf claudication relieved by rest.               |

## Proposal

| #   | Decision                                                                                                                                                                   | Recommendation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| V1  | Three new finding concepts (presence, `elicitedBy` required; onset, durationDays and severity optional; standard; no symptom code, since each is broader than any v1 code) | `sx.nausea_or_vomiting` "Nausea or vomiting"; `sx.vision_change` "Change in vision"; `sx.leg_pain_on_walking` "Leg pain on walking". Wording for the CSO.                                                                                                                                                                                                                                                                                                                                                                                    |
| V2  | The token map                                                                                                                                                              | The three symptoms map to the new concepts. The old concepts stay as they are (v1 drafts and the v1 desk still write them).                                                                                                                                                                                                                                                                                                                                                                                                                  |
| V3  | Engines that read the old concepts                                                                                                                                         | **`lib/ncd/cfc-map.ts` reads `sx.vomiting`** (`flag("vomiting", …)`). After V2, clerking v2 "Nausea or vomiting" no longer feeds it. Options: (a) leave it; the NCD engine then sees vomiting only from the v1 desk and triage; (b) also read `sx.nausea_or_vomiting`, which feeds nausea alone to a vomiting rule; (c) **recommended:** add a "which" property (nausea / vomiting / both) to `sym.nausea_vomiting` in catalogue v1.1, and chart `sx.vomiting` as well when the answer includes vomiting. (c) needs the catalogue v1.1 gate. |
| V4  | Delivery                                                                                                                                                                   | A signed data file `data/emr/clinical-fact-concepts.v1.4.json`, an `ADDENDA` entry, and one generated GATED migration (`0084_cfc_v1_4_history_breadth.sql`), applied by the owner after 0083. Signing charts only seeded concepts (M5), so code can ship first.                                                                                                                                                                                                                                                                              |
